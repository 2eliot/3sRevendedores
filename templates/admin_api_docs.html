Documentación de la API

Para conectar tu CRM: recargas, verificación de IDs de jugador y verificación de pagos de Bancamiga. El catálogo de juegos y paquetes de abajo se genera en vivo con los datos actuales de la web.

Inicio rápido

  • Dirección base: {{ api_url }}
  • Clave: en cada petición manda la cabecera X-API-Key: wsk_... con la clave de tu cuenta (Admin → API).
  • Formato: los datos se envían y se reciben en JSON (Content-Type: application/json).
  • Permisos: cada cuenta solo puede usar lo que tenga marcado en Admin → API: Hacer recargas, Verificar IDs de jugador y Verificar pagos de Bancamiga.
  • Saldo: cada recarga se cobra del saldo del usuario vinculado a la cuenta. Si falla, el saldo se devuelve solo.

Flujo recomendado para recargas automáticas

  1. El cliente paga por Bancamiga y manda la referencia y el monto por WhatsApp.
  2. Verificar pago (POST /api/verificar-pago) con la referencia, el monto y el ID de la orden del CRM. Solo sigue si responde "codigo": "aprobado" o "ya_aprobado".
  3. Verificar ID del jugador (POST /api/v1/verify-id), opcional, para confirmar el nombre antes de recargar.
  4. Recargar (POST /api/v1/recharge) usando el mismo ID de orden en external_order_id. Si por un fallo de red el CRM repite la petición, no se recarga dos veces.
  5. Si la respuesta tarda o se pierde, consulta el estado con GET /api/v1/order-status?external_order_id=....
Usa siempre el mismo ID de orden del CRM en los dos pasos. Así una referencia de pago nunca sirve para dos órdenes y una orden nunca se recarga dos veces.

Verificar ID de jugador

POST /api/v1/verify-id permiso: Verificar IDs de jugador

CampoTipoObligatorioDescripción
product_idnúmerosíJuego (ver Juegos y paquetes).
player_idtextosíID del jugador.
player_id2textosegún juegoSegundo ID, por ejemplo el Zone ID de Mobile Legends.
curl -X POST {{ api_url }}/api/v1/verify-id -H "X-API-Key: wsk_TU_CLAVE" -H "Content-Type: application/json" \
  -d '{"product_id": -1, "player_id": "123456789"}'
{"ok": true, "player_id": "123456789", "player_name": "ProPlayer99"}
{"ok": false, "error": "ID de jugador no encontrado"}

Máximo 30 verificaciones por minuto por cuenta.

Verificar pago de Bancamiga

POST /api/verificar-pago permiso: Verificar pagos de Bancamiga

CampoTipoObligatorioDescripción
referenciatextosíSolo números. Con 6 dígitos o más basta con los últimos dígitos.
montonúmero o textosíEn bolívares. Acepta 7350, 7350.00 o "7.350,00".
orden_idtextosíID de la orden en el CRM. Una orden nunca consume dos pagos.
fechatextosi la referencia tiene 4 o 5 dígitosAAAA-MM-DD.
horatextosolo si hay empateHH:MM o HH:MM:SS.
curl -X POST {{ api_url }}/api/verificar-pago -H "X-API-Key: wsk_TU_CLAVE" -H "Content-Type: application/json" \
  -d '{"referencia": "7568126123", "monto": 7350.00, "orden_id": "ORD-1001"}'
{"ok": true, "codigo": "aprobado", "mensaje": "Pago verificado",
 "pago": {"id": 31, "referencia": "7568126123", "fecha": "2026-10-05", "hora": "08:14:52",
          "monto": 7350.0, "tipo": "NC Fondos Recib. Terceros Otros Bancos", "estado": "usado"}}
codigoQué significaQué debe hacer el CRM
aprobadoPago válido; queda marcado como usado por esta orden.Recargar.
ya_aprobadoEsta orden ya tenía un pago aprobado (devuelve ese pago).Seguir con la recarga sin cobrar otro pago.
usadoReferencia duplicada: ya la usó otra orden.Rechazar y avisar al cliente.
no_encontradoTodavía no está en los movimientos del banco.Reintentar en 1 minuto (el banco se lee cada ~30 s).
monto_no_coincideLa referencia existe pero con otro monto.Pedir al cliente que revise el monto.
falta_fechaReferencia de 4 o 5 dígitos sin fecha.Pedir la fecha del pago.
revisionVarios pagos iguales. Si trae "pedir_hora": true, falta la hora; si no, quedó para revisión manual.Pedir la hora o pasar la orden a una persona.
ref_cortaMenos de 4 dígitos o con letras.Pedir la referencia completa.

Recargar

POST /api/v1/recharge permiso: Hacer recargas

CampoTipoObligatorioDescripción
product_idnúmerosíJuego.
package_idnúmerosíPaquete (solo los marcados como recargable).
player_idtextosíID del jugador.
player_id2textosegún juegoSegundo ID (Zone ID).
external_order_idtextomuy recomendadoID de la orden del CRM. Si se repite, devuelve la recarga existente y no cobra de nuevo.
curl -X POST {{ api_url }}/api/v1/recharge -H "X-API-Key: wsk_TU_CLAVE" -H "Content-Type: application/json" \
  -d '{"product_id": -1, "package_id": 1, "player_id": "123456789", "external_order_id": "ORD-1001"}'
{"ok": true, "order_id": 85, "status": "completada", "player_name": "ProPlayer99",
 "reference_no": "GP123456", "duration": 6.2, "remaining_balance": 149.14}

{"ok": false, "order_id": 86, "status": "fallida", "error": "ID de jugador no encontrado"}   ← el saldo se devuelve
{"ok": false, "error": "Saldo insuficiente", "saldo_actual": 0.5, "precio": 0.86}          ← HTTP 402
{"ok": true, "duplicada": true, "order_id": 85, "status": "completada", ...}               ← external_order_id repetida

La respuesta llega cuando termina la recarga (puede tardar varios segundos). Estados posibles: procesando, completada y fallida (con el saldo ya devuelto).

Estado de órdenes

GET /api/v1/order-status?external_order_id=ORD-1001

{"ok": true, "found": true, "status": "completada",
 "order": {"id": 85, "player_name": "ProPlayer99", "reference_no": "GP123456", "error": ""}}

GET /api/v1/orders/<order_id>

El mismo detalle, buscando por el order_id que devolvió la recarga.

Webhook (opcional): si la cuenta tiene una URL de webhook, al terminar cada recarga se envía un POST con {"event": "order.updated", "order": {...}}.

Saldo

Errores HTTP

HTTPCuándo
400Faltan datos o tienen un formato inválido.
401Falta la clave, es incorrecta o la cuenta está desactivada.
402Saldo insuficiente para la recarga.
403La cuenta no tiene permiso para esa acción.
404Juego, paquete u orden no encontrados, o verificación de ID no disponible para ese juego.
409Esa external_order_id tiene una recarga todavía en proceso.
422La recarga falló (el saldo ya se devolvió).
429Demasiadas peticiones; espera un minuto.
